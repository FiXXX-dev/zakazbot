# ZakazBot — приём заказов HoReCa

MVP веб-приложения для менеджера поставщика HoReCa: клиент присылает голосовое
сообщение или текст → система расшифровывает аудио (OpenAI Whisper),
нормализует текст (числительные, типичные ошибки, самоисправления),
разбирает заказ на позиции (GPT-4o-mini) → менеджер проверяет таблицу →
готовый Excel для 1С. Распознаёт русскую, узбекскую и смешанную речь.
Заказы и клиенты хранятся в Supabase.

```
Голосовое / текст клиента
        │
        ▼
   Whisper (расшифровка)
        │
        ▼
   Нормализация (ikki yuz → 200, ikta → ikkita, самоисправления yo'q/йук/ээ …)
        │
        ▼
   GPT-4o-mini (товары, количество, ед.изм., уверенность, самоисправления)
        │
        ▼
   Редактируемая таблица  ──►  Excel для 1С (SheetJS)
        │
        ▼
   Supabase (orders / clients / order_logs)
```

## Страницы

| Страница | Что умеет |
|---|---|
| `index.html` | Входящие заказы: статусы (new / processing / ready), поиск по клиенту, фильтр по статусу и дате (сегодня / всё время), смена статуса, скачивание Excel, удаление |
| `new-order.html` | Создание заказа: аудио (.ogg/.mp3/.wav/.m4a) или текст → «Распознать заказ» → редактируемая таблица позиций (жёлтым — что нужно уточнить), клиент и телефон, Excel, сохранение |
| `clients.html` | База клиентов: поиск, история заказов, стандартный заказ — подставляется, когда клиент говорит «как обычно» |
| `admin.html` | Импорт товаров (`products`) и клиентов (`clients`) из .csv/.xlsx (для своего аккаунта) |
| `login.html` | Вход и регистрация через Supabase Auth (email/пароль) |
| `dashboard.html` | Админ-панель владельца: все подписки, статистика, управление планом (basic/pro)/статусом (только для `ADMIN_EMAIL`) |
| `settings.html` | Тариф пользователя: текущий план, сравнение Basic/Pro, заявка на Upgrade |

## Стек

- **Frontend:** чистый HTML/CSS/JS, без фреймворков и сборки
- **Backend:** Supabase (Postgres + Edge Functions)
- **ИИ:** OpenAI Whisper (`whisper-1`) + GPT-4o-mini
- **Excel:** SheetJS (CDN)
- **Хостинг:** GitHub Pages (статика)

## Установка

### 1. Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. **SQL Editor** → выполните содержимое `sql/schema.sql`
   (таблицы `orders`, `clients`, `products`, `order_logs`, `subscriptions`,
   бакет `order-audio`, RLS по `user_id` + админ). Скрипт идемпотентен.
3. **Authentication → Providers → Email** — включите. Для мгновенного входа без
   письма временно выключите «Confirm email». В `config.js` и в функции
   `is_admin()` (в `sql/schema.sql`) укажите **один и тот же** `ADMIN_EMAIL`.
   После первого входа привяжите старые данные к своему аккаунту — см. блок
   «миграция существующих данных» в `sql/schema.sql` (`update … set user_id = …`).
4. Установите [Supabase CLI](https://supabase.com/docs/guides/cli) и
   задеплойте Edge Function с ключом OpenAI:

   ```bash
   supabase login
   supabase link --project-ref <PROJECT_REF>
   supabase secrets set OPENAI_API_KEY=sk-...
   supabase functions deploy openaiproxy
   ```

### 2. Конфигурация фронтенда

`config.js` хранится в репозитории (он нужен GitHub Pages) и содержит только
публичные значения. Впишите в него:

- `SUPABASE_URL` и `SUPABASE_ANON_KEY` — Supabase → Settings → API
  (anon-ключ публичный по дизайну);
- `OPENAI_MODE: "edge"` — оставить как есть: ключ OpenAI живёт в секретах
  Supabase, поле `OPENAI_API_KEY` в репозитории всегда пустое.

### 3. Локальный запуск

```bash
npx serve .
```

Откройте http://localhost:3000 — все три страницы работают как статика.

### 4. Деплой на GitHub Pages

1. GitHub → Settings → Pages → Deploy from a branch → ветка `main`, папка `/ (root)`.
2. `config.js` уже в репозитории — перед публикацией убедитесь, что в нём
   `OPENAI_MODE: "edge"` и `OPENAI_API_KEY: ""` (пустой!).

   Анонимный ключ Supabase — публичный по дизайну, его публиковать можно.
   Ключ OpenAI публиковать нельзя никогда: для режима `direct` вписывайте его
   только локально и не коммитьте такой файл.

## Режимы обращения к OpenAI

| Режим | Где живёт ключ | Когда использовать |
|---|---|---|
| `edge` (по умолчанию) | Секреты Supabase, в браузер не попадает | Всегда, включая прод |
| `direct` | `config.js` в браузере | Только локальная отладка |

## Распознавание

Конвейер: **Whisper → нормализация → GPT-4o-mini**.

**Нормализация** (`js/normalize.js` + словарь `js/dictionary.js`) выполняется
на фронтенде между расшифровкой и разбором. Она:

- сворачивает узбекские и русские числительные в цифры
  (`ikki yuz` → `200`, `besh ming` → `5000`, `двести пятьдесят` → `250`);
- отделяет узбекский счётный суффикс (`ikkita` → `ikki ta` → `2 ta`);
- исправляет типичные ошибки распознавания (`ikta`/`ixta` → `ikkita`,
  `plastik vilko` → `plastik vilka`);
- помечает **самоисправления** клиента (`yo'q`, `йук`, `нет`, `ne`, `ээ`,
  `ya'ni`, `aniqrog'i`, `to'g'risi`).

Словарь поддерживает оба алфавита (латиница и кириллица) и пополняется без
правки кода — только данными в `js/dictionary.js`.

**Системный промпт** (продублирован в `js/openai.js` и
`supabase/functions/openaiproxy/index.ts`) возвращает строгий JSON: клиент,
комментарий, флаги `urgent` / `repeat_last_order` и список позиций с
`confidence`, `confidence_score` (0–100) и `corrected`. Промпт инструктирует
GPT при самоисправлении брать **последнее** значение, а при повторе товара —
последнюю уточнённую версию. Понимает узбекские единицы (dona=шт, ta=шт,
juft=пар, qop=мешок, korobka=коробка, upakovka=упаковка).

**Определение клиента.** В записи может быть несколько имён («Добрый день,
Сулуддин. Добрый день, Миша…»). Модель возвращает все имена (`name_candidates`)
с флагом приветствия, а `js/client-detect.js` выбирает клиента: имена
сотрудников (`managerNames`) исключаются, имя из базы клиентов в приоритете,
среди равных предпочитается не приветственное обращение. Логику покрывают
тесты — `node tests/client-detect.test.js`.

В интерфейсе нового заказа видны три уровня: **исходная расшифровка →
нормализованный текст (со списком замен) → извлечённый заказ**. Позиции,
которые требуют проверки (нет количества, низкая уверенность или было
самоисправление), подсвечиваются жёлтым с процентом уверенности. Правка
менеджером снимает пометку. Фразы «как обычно», «как вчера», «повтори прошлый»
и т.п. берут за основу стандартный заказ клиента, а услышанные изменения
применяются к нему через `js/order-merge.js`: совпавшие позиции обновляются
(без дублей), «убери …» (qty=0) удаляет позицию, новые товары добавляются.
Цена подставляется из каталога `products` при однозначном совпадении названия.

**Логирование для обучения.** При сохранении заказа исходная и нормализованная
расшифровка, список замен, аудио (в бакет `order-audio`) и итоговый заказ
пишутся в таблицу `order_logs`. Это best-effort: сбой логирования не мешает
сохранению заказа.

## Безопасность (важно для MVP)

- RLS-политики открыты для `anon`: любой, у кого есть anon-ключ, может читать
  и менять данные. Для продакшена включите Supabase Auth и используйте
  закомментированный блок политик в `sql/schema.sql`.
- Ключ OpenAI хранится только в секретах Supabase (режим `edge`).
